# Todoist — タスクへの落とし込み

**手順そのものは `~/.claude/CLAUDE.md` の「🧱 作業の刻み方」にある。**
終了条件の導出4ステップ、判定基準、A / B / C の分岐、中断の扱い、
「外れたら分かる1行」は全部あちら。**ここに写さないこと。**
ここが持つのは Todoist 固有の部分だけ。

同期ルールと `no-ai` の扱いは `CLAUDE.md` の「✅ Todoist」節にある。
出典・経緯・「扱わない項目」は
`~/ghq/github.com/mimikun/mimikun.agent-system/todo.md` の
「「やり切る」のフォーマット作り」にある。

## どのタスクに適用するか

**終了条件が既に明確なタスクには何もしない。** ゴミ出し、繰り返しの定型作業、
フォーム送信のように、外部が完了を判定するものは対象外。手を入れると雑音が増えるだけ。

**判定者が自分しかいないタスクにだけ適用する。**

## 記入様式

```txt
タイトル: 終了条件の明確な、わかりやすいタイトル
説明:     タイトルが長くなりすぎたときだけ、補足する説明文章
```

- **終了条件はタイトルに入れる。** 本人が見ているのはタイトルだけなので、
  説明欄に置くと読まれない。
- **説明欄は補足であって再掲ではない。** タイトルの内容を書き直さない。
- **完了日時は書かない。** Todoist が完了時に自動で持つ。
- **本人に考えてもらう。うながして、待つ。自分から終了条件を書かない。**
  これは `CLAUDE.md` の「案を出す」既定の例外にあたる。

## 途中で切れたとき

「今日わかったこと」または「今日進んだところ」を
**1行だけ、そのタスクのコメント欄**に残して終わる。**1行あればその日は完了。**
コメント欄なのは、タスクと同じ場所にあって次に開いたとき必ず目に入るから。

## サブタスクにするか、説明欄に書くか

**分岐は「手順が時間か場所で分断されるか」だけで決める。**

- **分断される** → サブタスクにする。別々の日・別々の場所で想起される必要があり、
  **サブタスクごとに期日を持てること**が効く
- **一続きで終わる** → 説明欄に手順を書く。分断されないものをサブタスクにすると、
  1つの動作にチェックを何度も付ける作業が増えるだけで、**想起は1つも増えない**

**隣のタスクの形を写さない。** 2026-09-11 に実際にやった。既存タスクがサブタスク方式
だったので同じ形にしかけたが、そちらは工程が別々の日と別々の場所に分断されるもので、
新しいほうは机の前で15分で終わるものだった。**見た目が似ているだけで、分岐の条件は別。**

**飛ばされると高くつく手順が1つあるなら、サブタスクを生やさず終了条件に織り込む。**
説明欄は読まれない前提(上の「記入様式」)なので、そのためにサブタスクを1個だけ作るより、
タイトルの終了条件に入れるほうが安い。

## 親子タスクは2回に分けて作る

**1回の呼び出しで親と子をまとめて作らない。** 子は `parentId` に親の ID が要るが、
同じ呼び出しの中ではその ID がまだ存在しない。**まとめて渡すと親子にならず、
フラットに並ぶか1つのタスクに潰れる。**

1. **親だけ作り、返ってきた ID を受け取る**
2. **その ID を `parentId` にして子を作る**

**本人からの指摘で判明**(2026-09-05)。「親子タスクにしてほしいけど、なぜか
ひとまとまりのタスクになる」。**原因は Todoist 側ではなく、この手順を踏んでいなかったこと。**

## 上限に当たったら、プロジェクトを分ける

追加が `MAX_ITEMS_LIMIT_REACHED`(HTTP 403, code 49)で落ちることがある。
**上限はアカウントではなくプロジェクト単位。**

- **既存タスクを消して枠を空けない。** 同じ壁にまた当たる
- **量の多い一群を別プロジェクトへ移す**のが対処だが、**下の警告を先に読むこと**

### ⚠️ サブタスクの多い親の移動は破壊的操作

**Todoist の Known issues に載っている既知の不具合**（2026-09-05 に公式ページで確認。
修正目標は2026年末）。

> サブタスクを多数持つ親タスクを移動すると同期エラーが出ることがある。
> **そのエラーを閉じると、親とサブタスクが全プラットフォームから消え、復旧できない。**

したがって:

- **移動の前に本人の承認を取る。** 元に戻せない可能性がある操作なので、
  「低リスクで元に戻せる手順」には該当しない
- **可能なら小分けに移す。** 親ごと一度に動かさず、サブタスクを小さな群に分ける
- **同期エラーが出たら、閉じずにその場で止めて本人に知らせる。**
  Todoist サポートへの連絡が要る。**閉じた時点で復旧手段が無くなる**
- **移動後は必ず件数を数える**（`find-tasks` の `projectId` 指定）。
  移動元と移動先の合計が一致するか見る

**2026-09-05 に、この警告を知らないまま親1件を動かして 100件超を移動した。**
結果は無事（移動後に119件を確認）だったが、**運が良かっただけで手順として正しくない。**
上の4点はその後に追記したもの。

## 構造の注意

- 親タスクを別プロジェクトへ移動すると、サブタスクも一緒に付いていく。
  `projectId` の更新はトップレベルのタスクにだけ行う。
